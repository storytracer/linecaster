    Changelog¶

    All notable changes to linecaster. The format follows Keep a Changelog; each release lists upgrade notes first, then additions, changes, deprecations, removals and fixes. Versions follow the tags; the first is v0.1.0.

    Unreleased¶

    Added¶

    • Versioned docs: the docs workflow publishes the site with mike to the gh-pages branch, served by GitHub Pages: every release tag as version <major>.<minor> (latest the newest release, the default), every push to main as dev; mike joins the dependency group docs.

    0.1.0 (2026-11-06)¶

    Upgrade notes¶

    The first release, after the refactoring of November 2026 in six phases; each phase's renames are listed here, and all of them in one table at the end of these notes. There are no compatibility aliases: old imports, flags and ids fail.

    Phase 1: layout and names

    • Packages: linecaster.transcription, linecaster.page → linecaster.data (data model) and linecaster.formats (ALTO, PAGE, hOCR; formats.docling was linecaster.document); text.py, unicode.py, reflow.py, retyper.py → linecaster.text.variants, .unicode, .recomposition, .typography; images.py, plots.py → linecaster.images; run, jobs, ray_executor, provenance → linecaster.runtime.* (run.rows() → run.pages()); linecaster.models → linecaster.adapters; blocks/http.py → linecaster.net; blocks by family under linecaster.blocks.<family> (old modules filters, media, models, serve, texts, document, readers, writers are gone); specs/ → docs/reference/.
    • Blocks: PageStep → PageBlock, ModelStep → ModelBlock, WorkingImages → ImageConverter, AttachImage → ImageFetcher, LayoutStep → LayoutDetector, LinesStep → LineDetector, AssignLinesToRegions → LineAssigner, RecognitionStep → LineRecognizer, ChatRegionStep → RegionRecognizer, ChatPageStep → PageRecognizer, TablesStep → TableRecognizer, FormulasStep → FormulaRecognizer, NormalizeUnicode → UnicodeNormalizer, Typography → Typographer, ComposePage → Composer, ValidatePages → PageValidator, RejectSink → RejectWriter, RecipeStamp → RecipeStamper, ServeModels → ModelServer, ServeChatModel → ChatModelServer, PageRowReader → PageRecordReader; writers: PageFilesWriter + PageExportsWriter → PageFileWriter (text_fallback=False is the old PageExportsWriter), ItemExportsWriter → ItemDocumentWriter, ItemTextJsonlWriter + ItemTextFilesWriter → ItemTextWriter(format=...). Datatrove display names changed with them (stats and logs).
    • Engines: …Model → …Engine (KrakenRecognitionEngine, PaddleLayoutEngine, ...); ids unchanged. Adapters: ChatModel → ChatAdapter, each VLM adapter X → XAdapter.
    • Pipeline scripts: transcribe_chain.py → transcribe_modular.py; ids chain.v1 → transcribe_modular.v1, vlm.v1 → transcribe_vlm.v1, new harvest.v1, bind.v1.
    • Flags: --recognizer → --recognition; --vlm, --vlm-endpoint → --recognition, --recognition-endpoint; --texts → --item-texts; --exports DIR → --files DIR --formats md,txt,json --naming squiddleocr --furniture; --rows → --pages.
    • Stored output: the default transcription ocr → ocr_new; page records in OUT/rows/ → OUT/pages/; item text fidelity normalised → normalized; typography measurement levelled → leveled. Page records written before phase 1 keep ocr; read them with transcription="ocr".
    • Catalog: no step page (page presets are step recognition, unit page, under presets/recognition/); entries are <id>.yaml with prose in <id>.md; YAML is read as YAML 1.2 with ruamel.yaml (replaces PyYAML); lock format linecaster.lock/2. Edition numbers are unchanged; 20 hashes were recomputed (the page presets and squiddle@1), so files stamped by a recipe carry the new hash; old hashes still resolve (previous_sha256).
    • American spelling throughout (e.g. normalize, NORMALIZE_MAP, quantize_confidence, COLORS).

    Phase 2: contracts and the builder

    • Pipeline scripts check their pipeline before they launch: a pipeline whose contracts do not fit exits with code 2 and lists every problem. Own blocks without a contract() pass unchecked.
    • With --tasks over 1, a binder after the page blocks (--item-texts) cuts the run into two stages: page records in item shards (OUT/pages/<shard>/), then the item stage; their logs are OUT/logs/pages/ and OUT/logs/items/. One stage logs to OUT/logs/ as before.
    • --dry-run prints the plan under plan and the Mermaid graph after the JSON.
    • A page an in-process block fails on no longer fails the task: it carries the error (doc.metadata["errors"]: block, step, preset, type, error; served failures in the same shape, no longer {step, error}), later model blocks pass it on at once, and it is written to OUT/rejects/<rank>.jsonl and kept in the page records. More failures than --max-page-errors (1 % of a task's pages, counting at least 100) fail the task.
    • ImageConverter(output_folder, rejects_folder, ...) → ImageConverter(output_folder, ...) and PageValidator(rejects_folder, required, prefix) → PageValidator(required): they record why on the page and pass it on (no longer dropped); the RejectWriter (now a writer block, RejectWriter(output_folder, prefix=""), which the builder puts before the first writer of a run) writes the rejects. A derivative that used either adds a RejectWriter where it wants the file, or lets the builder add one.
    • Library code raises linecaster.errors (PipelineConfigError, CatalogError, PageError, ServerError) instead of SystemExit, ValueError, KeyError, RuntimeError and TypeError for configuration, catalog, page and server errors (e.g. an unknown preset is a CatalogError, an unknown block option a PipelineConfigError); pipeline scripts raise PipelineConfigError from pipeline().
    • runtime.jobs.dependencies(commit) without a script raises; give the pipeline's script, runtime.jobs.ENGINE_SCRIPT (the modular pipeline's engines) or engines=False (linecaster alone).
    • The run record's schema is linecaster.run-record/1 (was linecaster.run/1): pipeline lists the stages with every block's to_dict() and contract (was a list of block entries; the separate stages is gone), and pipeline_sha256 is new. A run into an OUT whose record has another pipeline_sha256 (or none: a record from before) is refused unless --new-pipeline; another --tasks always is.
    • Page records carry schema: linecaster.page/1 in their row. Records without one (written before phase 1) are read with ocr as ocr_new, and a pages/ folder without records is read from its sibling rows/: no transcription="ocr" needed any more.
    • Engines load in warm_up() before the first page, not on it: a page's measured seconds no longer include loading; the load time is the block's warm_up_seconds stat. ModelServer and ChatModelServer start their servers in warm_up() (stat warm_up_seconds, was the boot time stat).
    • engine_spec(ref) and preset_models(models) take installed=True; tests that replace engine_spec accept it.
    • On HF Jobs the tasks log JSON lines (LINECASTER_LOG_JSON=1, runtime.jobs.JobsExecutor; the run record's executor is JobsExecutor).
    • Every run is traced (OpenTelemetry, a new required dependency: opentelemetry-api, -sdk, -exporter-otlp-proto-http): OUT/traces/ appears in every run folder, and a sampled page's record carries metadata.trace_id. Every stage with a run folder now has observers, so its pipeline has boundary steps.
    • Observers: on_task_end(error=None) (was on_task_end(); an own observer adds the parameter), and new hooks on_task_event, on_leave, environment(). Stream blocks notify request (with a carrier) after prepare, and done with tokens and finish_reason; PageRecognizer notifies prepare once (was twice).

    Phase 3: rule-based steps, recomposition, binding

    • Text without geometry (lines without boxes, e.g. a delivered plain text): a paragraph now continues across a page break only after a division mark; before, the simple line flow joined such pages whenever the text did not end a sentence.
    • linecaster.blocks.writers.item_texts(doc, variants, transcription, token_counter) renders an item record's text variants as datatrove documents, for derivatives writing them in a format of their own; ItemTextWriter uses it.
    • linecaster.catalog.schema.RULE_STEPS lists the rule-based steps, to tell a recipe's rule-based slots from its model slots.
    • Data model: ModelInfo → StepInfo (new field engine, the engine's code id, filled by the model blocks, linecaster serve and the chat adapters), Transcription.model → Transcription.steps, ChatAdapter.model_info() → step_info(). New: Transcription.paragraphs (Paragraph, ParagraphRow, ParagraphRef, Decision), Line.normalized, and the measurements vocabulary linecaster.data.MEASUREMENTS (the keys a step writes; an engine package in this repository adds a new key there first, a test checks it).
    • Page records are linecaster.page/2 (steps instead of model, paragraphs, normalized). PageRecordReader reads linecaster.page/1 records and those from before phase 1 as /2; code that reads the JSON itself reads steps.
    • The page files' step records (ALTO processingStepSettings, PAGE Labels, hOCR linecaster-step-<n>, METS agents) carry engine for steps an engine ran.
    • Catalog: the steps image, normalization, typography, recomposition, composition with built-in engines in linecaster.engines, in-process only (linecaster serve refuses them); presets may name by_script strategies; capabilities.unit may be item and produces names parts (PARTS). preset-1.json gains them; no released hash changes. engine_spec(ref, installed=True, served=False) and preset_models(models, installed=True, served=False): tests that replace engine_spec accept served.
    • regex is a new core dependency (Unicode scripts).
    • The rule-based blocks take a preset or an engine spec, with options over it: Typographer() → Typographer("ratios@1"); Composer(text="reflow", sections=..., rtl=...) → Recomposer("unicode-recomposition@1", options={"rtl": ...}) + Composer("docling-composition@1", options={"sections": ...}), and text="lines" is a Composer without a Recomposer before it (the document is composed from paragraphs when there are, else from lines); ImageConverter(output_folder, effort=80) → ImageConverter(output_folder, "working-image@1", options={"effort": 80}). New blocks Recomposer (composition, unit="page"|"item") and CharacterNormalizer (text); Composer also takes unit="item".
    • DocumentBuilder(name, text=..., sections=..., rtl=..., stats=...) → DocumentBuilder(name, sections=...): it no longer recomposes, it composes a page's paragraphs when it has them (add_page(..., page_id=...) names the page for paragraphs continued across pages); build_docling(...) loses text, rtl and stats; formats.docling.TEXT_MODES is gone. In linecaster.text.recomposition, join_paragraphs → join (the joined text, the separator and the decision on the division mark), new break_reason, kept_reason, mark_decision, Thresholds (the geometric thresholds and the convention marks, parameters of reflow_rows, Margins.of, continues, ...); Row.bbox may be None (text only). text.typography.retype takes ratios (Ratios) and records no step (the engine does); typography.SETTINGS is gone.
    • Page records and page files: with a recomposition (--recomposition, the squiddle recipe) the transcription carries its paragraphs (with their decisions); the typography step is recorded by its engine (name and engine typography.ratios.v1, preset ratios@1 and its hash, every option as settings, seconds and datetime), and the recomposition and composition steps have step records of their own. The documents and their exports are unchanged.
    • Binding: BindItem and ItemTexts are removed. BindItem(text="reflow", sections=S) → Binder() + Recomposer("unicode-recomposition@1", unit="item") + Composer("docling-composition@1", unit="item", options={"sections": S}) (text="lines": without the Recomposer); the item documents are the same, the item document's metadata is the item record plus docling, region_of, item_id (no page_ids, pages, text_mode, sections). ItemTexts(variants=V, token_counter=F) → Binder() + Recomposer(..., unit="item") + CharacterNormalizer("latin-historic@1", unit="item") + ItemTextWriter(DIR, variants=V, token_counter=F): the writer renders the variants from the item record (one row per item and variant, the same columns). ItemDocumentWriter gains by_format (<format>/<item>.<ext>).
    • The readable variants (readable_txt, readable_md) are made from the item's recomposition and normalization (Paragraph.normalized) instead of text.variants' own line flow, so they change (paragraph breaks, kept hyphens; NOTES.md has the comparison). linecaster.text.variants: join_lines, page_blocks, item_blocks, continues, HYPHENS and SENTENCE_END are gone; variants(pages, page_ids=None) needs recomposed, normalized pages; body_blocks and Block.normalized are new. The normalization engines also set each table cell's normalized.
    • pipelines/transcribe_modular.py: --text lines|reflow → the slots --typography, --recomposition, --normalization and --composition (presets; an empty slot leaves the step out: --text lines is no --recomposition). Without a recipe the rule-based steps run only when picked (before: typography and composition always). --item-texts needs --recomposition and --normalization (the recipe squiddle has them). --set takes the rule-based steps too (--set composition.sections=true).
    • pipelines/bind.py (bind.v1, now with recipes): Binder → item recomposition → normalization → item composition, texts in OUT/texts/<variant>/ (JSONL; --files also one file per item there, was OUT/files/<variant>/) and item documents in OUT/documents/<format>/; slots --recomposition, --normalization, --composition (the new recipe item-texts@1 fills them), --variants, --formats, --furniture, --dividers, --no-texts, --no-documents, --set.
    • squiddle@1 names the rule-based presets (ratios@1, unicode-recomposition@1, latin-historic@1, docling-composition@1) instead of the option text: reflow: a catalog migration, so its hash changed (files stamped by it carry the new one) and the lock's previous_sha256 lists both earlier hashes (previous_sha256 may now be a list, oldest first; Resolved.previous_sha256 is a tuple).
    • The builder carries the parts across a binder and a splitter (an item record holds its pages), apart from image and the item's document; the role splitter is new. Recomposer's contract replaces paragraphs too (it makes them anew). RecipeStamper has unit any (it stamps the pages of item records).

    Phase 4: backends and families

    • VLMs are the Chat backend (linecaster.backends.Chat(preset, endpoint=None, served_name=None, max_window=32, initial_window=4, read_timeout=600.0, api_key=None, headers=None, prefer="page")): PageRecognizer(spec, Served(endpoint, model=name, max_window=W, ...)) → PageRecognizer(Chat(spec, endpoint, served_name=name, max_window=W, ...)), the same for RegionRecognizer(spec, backend, labels=..., pad=...) → RegionRecognizer(Chat(...), labels=..., pad=...); either also takes a chat preset's ref (PageRecognizer( "dots-ocr"): on the task's ChatModelServer, port 8000). The adapter is block.adapter (was block.spec), the served name Chat.served_name (was the Served backend's model). Without an endpoint Chat asks http://127.0.0.1:8000/v1. The page records are unchanged.
    • The run record: a chat block's parameters are backend ({"backend": "chat", "adapter", "preset", "preset_sha256", "model", "revision", "served_name", "endpoint", ...}) instead of spec and a served backend; pipeline_sha256 covers the adapter, preset edition and hash, model and revision (no longer the served name), so a run of transcribe_vlm.py into an OUT of before is refused unless --new-pipeline.
    • ModelBlock streams for every served block, and a block names its requests with _rows, _unit, _request, _parse and _done (an own served block that overrode _run_served or RegionRecognizer._run_regions uses them). Model blocks also take a preset ref as their backend (LayoutDetector("pp-doclayoutv3@1"): in-process).
    • SingleRegionLayout is removed: SingleRegionLayout() → LayoutDetector("single-region@1") (the built-in engine layout.single-region.v1; label and region_id are its options). The region is the same; the page now records a layout step for it (engine, preset, settings, seconds, datetime), which page files list too, and the block reads the page image instead of the record's size. ModularTranscriber(lines, recognition) needs its layout: ModularTranscriber(lines, recognition, "single-region@1").
    • pipelines/transcribe_modular.py needs --layout like --lines and --recognition: a run without one is --layout single-region. Presets of built-in engines stay in-process with --backend served (runtime.run.engines), and the pipelines' serve leaves them out.
    • ManifestReader(existing_ocr=True) only fetches the library's OCR, as a document media with metadata["format"] (alto, hocr); its contract adds transcription_file (a new page-level part) instead of ocr_original:*. The TranscriptionConverter reads it into ocr_original: the builder puts one right after such a reader when no block reads the file, and pipelines/harvest.py has its own, so OUT/ocr/ and the page records are as before. Its hash changes (a new block), so a harvest into an OUT of before needs --new-pipeline. A file that cannot be read is now the page's error (it goes to rejects/; before, the page went on without it and ocr_failed counted it); a failed download is still counted as ocr_failed. hOCR files that state another image size are scaled to the page image (before: read as they were).
    • PARTS gains transcription_file (no released hash changes).
    • A new extra, [pypdfium2], for the PdfReader; the locks list it.

    Phase 5: docs

    • linecaster catalog docs [--out docs/catalog] [--readme README.md] → linecaster docs [--out docs] [--readme README.md] [--check]: --out is now the docs folder (the catalog's pages go to <out>/catalog/). It also writes the block pages, the README's block table (between <!-- blocks:start --> / <!-- blocks:end -->), the site's docs/index.md and docs/changelog.md, and docs/llms.txt / docs/llms-full.txt; --check writes nothing and exits with 1, naming each file that differs. linecaster catalog no longer has the action docs.
    • Generated pages start with a comment saying so; their links to files outside docs/ (sources, pipeline scripts, model cards) go to GitHub. The evidence tables have two more columns, Hardware and Backend.
    • A new dependency group, docs (MkDocs and Material), not an extra: uv run --group docs mkdocs build --strict.
    • CLAUDE.md holds rules only; what it described is in docs/reference/architecture.md, the data model and serialization pages.

    Phase 6: tests and engine hygiene

    • Contracts name the parts a block removes (Contract.removes, parts_removed; the run record's contracts and schemas/run-record-1.json have removes). ImageConverter without keep_bytes removes image: a pipeline in which a later block reads the image (without an ImageFetcher in between) no longer passes the builder's check; it failed on its first page before.
    • RegionRecognizer(pad=None): an explicit pad wins over the adapter's region_pad, which is the default (else 8). Callers that passed pad with a preset that has a region_pad (minicpm-ocr-1.0: 0, lightonocr-2-1b-regions: 8) now get their pad. The run record names pad: null when none is given, so pipeline_sha256 of a pipeline with a RegionRecognizer changes (no released recipe has one): resuming into an older run folder needs --new-pipeline.
    • Engine packages are version 0.1.0 and depend on linecaster>=0.0.1,<0.2; they import from linecaster only linecaster.data and linecaster.engines.api. A derivative's own engine package should do the same.
    • Tests: pytest runs with --strict-markers; tests/conftest.py's make_transcription is linecaster.testing.sample_transcription.

    Added¶

    • linecaster.testing: sample pages (sample_page, sample_boxes, sample_png, sample_layout, sample_document, sample_documents, sample_transcription); fake CPU engines (FakeLayoutEngine, FakeLineEngine, FakeRecognitionEngine, FakeTableEngine, FakeFormulaEngine), registered as fake.<step>.v1 by register_fakes() (catalog.registry.REGISTERED); fake_chat_server() and completion(); the conformance checks check_engine and check_block (with transcription_changes and page_changes); the pytest markers and hooks (linecaster.testing.markers). Every built-in engine and every public block has a conformance test.
    • linecaster.engines.api: the Engine protocol, Capabilities, weights_of, hf_file, hf_snapshot, model_entry.
    • Markers gpu, network, slow, parity; gpu and network tests skip where the device or the network is missing.
    • Tests of each engine package in engines/<engine>/tests/ (conformance on the CPU, and on CUDA for kraken, and units), run with uv run tests/test_engines_catalog.py engines/<engine>/tests; the engine READMEs give the install and test commands.
    • A missing engine's CatalogError names the engine package that provides it and the pipeline scripts that install it (catalog.code.install_hint).
    • The CI workflow .github/workflows/ci.yml (CPU, no secrets): uv sync --locked --all-extras, the tests without gpu, network and parity, linecaster docs --check, linecaster catalog verify, the strict site build.

    • tests/integration/ray_data_spike.py: the squiddle blocks through Ray Data (NOTES.md, 2026-11-06).

    • The block pages (docs/blocks/): an index by family and a page per block with its contract, backends, catalog step and presets, where it comes in a pipeline, the pipeline scripts that use it, its options, behavior and example, all from code; blocks whose constructor needs arguments declare docs_args for them.

    • The docstring standard (docs/reference/conventions.md, "Docstrings") and tests/test_docstrings.py: every public block, built-in engine, backend, serializer, build, run_pages, runtime.run.main and public catalog function has a summary line and Args: for its whole signature; examples for the serializers, build, main and the catalog functions.
    • docs/reference/architecture.md, docs/reference/compatibility.md (what counts as a breaking change), READMEs for the engine packages, and the docs site (mkdocs.yml).

    • Tests: the generated docs are current, and the README's "Your own pipeline" builds and checks.

    • The Chat backend (linecaster.backends.Chat) for PageRecognizer and RegionRecognizer.

    • TranscriptionConverter(format="auto"|"alto"|"page"|"hocr"|"text", source="media"|"uri", transcription="ocr_original", uri_key=None) (conversion): a library's own transcription delivered with the page, or named by a URI in its metadata, read at the page image's size.
    • The engine layout.single-region.v1 and its preset single-region@1.
    • IIIF Collections (a skeleton): ManifestReader reads a collection entry as its manifests, one item each, one level deep (a collection in a collection raises NotImplementedError), with pybookget's read_collection (a pybookget that has it).
    • PdfReader(data_folder, paths_file=None, glob_pattern="**/*.pdf", dpi=300, ...) (a skeleton, extra [pypdfium2]): one item per PDF, its pages rendered as lossless WebP; the text layer (text_layer=True) raises NotImplementedError.
    • Block contracts (contract(), Part, Contract, PARTS), the builder (linecaster.runtime.builder: build, Plan, checks, branches with when=/group=, composites, stages, run_pages), observers (linecaster.runtime.observers), the composite ModularTranscriber, the error classes (linecaster.errors), partial runs (--until, --after, --tap-after), --page IMAGE and linecaster page; docs/reference/pipelines.md.

    Fixed¶

    • PageRecordReader(fetch_images=True), ImageFetcher and ImageConverter dropped the fragment of page.image.uri and fetched the whole file: for a PdfReader page (file.pdf#page=n) the PDF, for an ImageParquetReader row with embedded bytes the Parquet file. A PDF page is now rendered as PdfReader renders it (at the record's metadata["pdf"]["dpi"]), a Parquet row's image read (columns id and image), and any other fragment is the page's error (field image), never the wrong bytes (linecaster.blocks.readers.fragments).
    • ImageConverter without keep_bytes declared only metadata replaced although the page leaves without its image bytes: its contract now removes image, so the builder no longer treats the image as available after it.
    • ImageFilesWriter rewrites page.image.uri and extra (to name the copy) without declaring it: its contract now replaces metadata.
    • RegionRecognizer replaces the transcription's earlier lines but declared lines only as added: its contract now replaces lines and text, so it may follow a line step.
    • RegionRecognizer ignored an explicit pad when the adapter has a region_pad.
    • RegionRecognizer failed the task on a page without image bytes; the page now carries the error (found by check_block).

    • PageValidator(required=("image",)) declared that it reads the image bytes, although it checks the page record's image entry: a page field is now read as metadata, so the validator may follow an ImageConverter that removes the bytes.

    • PageParquetWriter writes a fixed schema: datatrove took a file's columns from its first row, so a page's errors were dropped when the first page of a file had none. Page records in Parquet now always have an errors column (null without errors).

    • Tracing holds no page documents: a page a block drops no longer stays in memory, with its image, until the task ends; its trace ends when the next page enters that block.
    • A sampled page's metadata.trace_id is derived from the run and the page id, so a rerun of a run writes the same page records.
    • runtime.jobs.dependencies() reads the pipeline script and its lock as they are at the commit the Jobs install, not as the checkout holds them (with a warning when the commit is not in the checkout).
