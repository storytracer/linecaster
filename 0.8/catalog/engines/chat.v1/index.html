chat.v1¶

Engine · recognition · package linecaster

Base class of a chat-VLM adapter. A subclass sets adapter (its registry name) and implements request; parse has a text-only default. Every value comes from the preset:

  • model / revision: the Hugging Face id and pinned commit; served_name: the name the server hosts it under (options.served_name, default the Hub id);
  • sampling, prompt, page_longest (the page size the model expects, longest side in px; also the scale RegionRecognizer cuts regions at), region_pad and the adapter's own settings;
  • server (vllm or sglang), server_version, job_image, serve_args (the server's flags after the model, not port/host) and server_env from the serve block;
  • revision_flag (pass --revision; False for a server that must load the default branch, which the serve block then checks file by file against the pin, pin_ignore aside) and server_packages (installed into the server's Python first) from the serve block or, until the serve schema has them, options.

A run may set the options of Options over the preset's settings (chat_model(..., overrides=...), --set recognition.<option>=<value>): max_tokens, temperature and top_p replace the preset's settings.sampling values; repair_max_tokens and repair_temperature its settings.repair values (max_tokens and temperature; default off, and 0.1); repetition_detection its settings.sampling.repetition_detection (below). The values that differ from the preset's are the adapter's overrides, recorded with it (to_dict()) and so in pipeline_sha256.

Repetition detection (repetition_detection): vLLM's own guard against a completion that loops (RepetitionDetection), sent with every request of the page (its repairs too). A loop then ends early with finish_reason repetition: the text as returned (what came before the loop and the repeats up to the stop), counted (stat finish_repetition) and never repaired. On by default wherever the preset's server takes it (vLLM 0.17.0 and later, by the preset's serve.version: takes_repetition_detection), with linecaster's defaults, unless the preset's settings or the run set it: false turns it off, true gives the defaults, repetition_detection.<field>=<value> sets one field over the preset's (or the defaults). An older vLLM, SGLang or another server would ignore the field silently: there it is off by default, and asking for it is refused (PipelineConfigError). The setting in effect is in the step's settings and, while on, in the adapter's record (to_dict()) and so in pipeline_sha256.

The repair pass (repair_max_tokens above 0; PageRecognizer runs it): a page whose completion stopped at max_tokens (finish_reason == "length") is sent once more, the same request (the same image and prompt, the same top_p) with max_tokens raised to repair_max_tokens (less where the served context leaves less room: repair_cap) and the temperature repair_temperature. The repair's completion is kept where it finished ("stop"), the first one otherwise, even when the repair's is longer. With a list of caps (repair_max_tokens: [8192, 12288]) a repair that stops at its cap is sent once more with the next, and the page keeps the first completion that finished, else its first one. The procedure is the reference script's (uv-scripts/ocr lighton-ocr3-saturate.py at e2b0aa5, its docstring "Truncation and repair"), which repairs at the end of a run; PageRecognizer repairs a page as soon as its first completion is back, with the same outcome. A completion cut off at max_tokens is often a repetition loop, which a repair does not end, but a dense table can simply need more tokens and finish with more room. repair_max_tokens must be larger than max_tokens (PipelineConfigError).

Options¶

Option Type Default Description
max_tokens int | None None the completion's cap (default: the preset's settings.sampling.max_tokens)
temperature float | None None the sampling temperature (default: the preset's)
top_p float | None None nucleus sampling (default: the preset's); the repair pass keeps it
repair_max_tokens int | list[int] 0 the repair passes' caps: a page whose completion stopped at max_tokens is sent again with the first cap, and again with the next while it stops at its cap (a number: one repair; a list: one per pass, rising, the first larger than max_tokens; 0 or []: off; lightonocr-3-0.8b@3: [8192, 12288], twice and three times its 4096)
repair_temperature float 0.1 the repair pass's temperature (the reference script's, uv-scripts/ocr lighton-ocr3-saturate.py at e2b0aa5)
repetition_detection RepetitionDetection | StrictBool | None None vLLM's repetition detection (vLLM 0.17.0 and later; on by default there): false turns it off, true gives the defaults (patterns of 8 to 100 tokens repeated 16 times), or its fields; repetition_detection.min_count=12 sets one field
