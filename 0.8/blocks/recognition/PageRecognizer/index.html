PageRecognizer¶

Block · recognition · linecaster.blocks.recognition

Recognizes every page with a chat VLM or a page engine, whose output becomes the page's transcription.

The contract is that of PageRecognizer(backend='lightonocr-2-1b@1'); the comes-after and comes-before rows are derived from every block's contract.

Options¶

Option Type Default Description
backend Chat | InProcess | Served | str required a Chat backend, an InProcess or Served backend of a page engine, or a preset's ref: a chat preset's (or a model's Hugging Face id: its page preset) for Chat on the task's ChatModelServer, a page engine's for its engine in the pipeline's process; a preset of another unit or any other backend is refused (PipelineConfigError).
transcription str 'ocr_new' the transcription the completion becomes.
primary str | None None the transcription whose text becomes the datatrove document's text; None: transcription.
skip_on_error bool True pass pages that carry errors through unprocessed.
prepare_workers int 4 threads that build requests ahead of admission (decode, resize and PNG-encode the image; Pillow releases the GIL).
name str | None None the block's name in stats and logs; None: "page (<model>, served <endpoint>)".
repair_only bool False send only the repair pass, for the pages of earlier page records that need it (a Chat backend with repair_max_tokens set; PipelineConfigError otherwise).

Behavior¶

On the Chat backend (served only) a stream transform: one request per page, built by the preset's adapter from the page image, the completion parsed into a new transcription (ChatAdapter.parse: its annotator, the completion verbatim as its raw output, and what was parsed from it) that replaces transcription. The completion's finish_reason and token counts go to its raw output and the annotator's measurements, and a completion cut off at max_tokens is counted (stat finish_length).

The repair passes (the chat option repair_max_tokens: a cap, or a list of rising caps, one per pass; linecaster.adapters.ChatAdapter): a page whose completion stopped at max_tokens waits in the block while its repair request goes into the same window at once (the same request body, so the same image and prompt and top_p, with max_tokens raised and the repair temperature); the other pages stream on. A repair that stops at its cap too is sent again with the next cap, until one finishes or the caps run out. Each repair's max_tokens is its cap, at most the served context minus the page's prompt tokens (the context from the server's /models max_model_len, else the preset's --max-model-len); where that is not above the cap before it, no more repairs are sent (none at all: stat repair_skipped). The page keeps the first completion that finished ("stop"), its first one otherwise: every request is one of the transcription's raw outputs (the completion verbatim, finish reason, tokens, pass 1, 2, ... and in settings the max_tokens as sent, temperature, top_p and preset), kept on the one the transcription's annotations were parsed from. The annotator's measurements sum the tokens of every request and list them per request (pass_prompt_tokens, pass_completion_tokens), its finish_reason is the kept one's; its settings add repair. Pages that stopped otherwise are recorded as without repairs (one raw output, no settings). A repair request that fails ends the repairs, and the page keeps what the passes before it give (stat repair_errors), not an error of the page. A page record is written only after its repairs, so an interrupted task sends every request again. Stats: finish_length (first requests), repair_sent (repair requests), repair_stop, repair_length (their finish reasons), repair_kept (pages that keep a repair), repair_skipped, repair_errors.

With repair_only it reads page records written earlier (PageRecordReader) and sends only the repair requests, by the same rules and recorded the same way: for the pages whose transcription's first completion stopped at max_tokens and has no repair yet (one raw output of the chat annotator, as linecaster writes a page without the repair pass or without room for it). Every other page passes through unchanged, without a request (stat repair_not_needed). The first request's prompt tokens and sampling come from the record. Where a repair is kept, the transcription is its parse, with the record's annotators (the chat annotator's place taken by the repair's) and every raw output; where none is, the record's transcription stays, with the repairs' raw outputs added.

On the InProcess or Served backend it runs a page engine (an engine of the recognition step whose unit is the page: a vendor package, or a client of a vendor's service) as every model block runs its engine: the engine gets the page image and returns the page's transcription. Either way it reads the page image and adds text and what the preset produces (lines, markdown, html, ...); the Annotator records the preset edition and its hash. A failed request or call is the page's error.

Example¶

from linecaster.backends import Chat

PageRecognizer("lightonocr-2-1b@1")
PageRecognizer(Chat("lightonocr-2-1b@1", "http://127.0.0.1:8000/v1", max_window=48, initial_window=8))
PageRecognizer(Chat("lightonocr-3-0.8b@2", overrides={"repair_max_tokens": [8192, 12288]}))   # repair passes
PageRecognizer("indra-ocr@1")             # a page engine, in the pipeline's process
